## 三、每节课的结构

沿用阶段 3 已经落库的 15 个内容模块，字段一一对应 `course_contents` 的列：

| # | 模块 | 数据库列 | 本阶段写作要求 |
| --- | --- | --- | --- |
| 1 | 学习目标 | `learning_objectives` | 3—4 条可检验的能力目标，动词开头 |
| 2 | 为什么学 | `why_learn` | 从真实痛点切入（参数一路往下传、报表算错、上线差环境） |
| 3 | 核心概念 | `concept_explanation` | 定义 + 关键术语，用列表而非长段落 |
| 4 | 通俗解释 | `plain_explanation` | 生活类比，独立成段，不与核心概念重复 |
| 5 | 语法介绍 | `syntax_explanation` | 可直接复用的代码模板 + 注意事项 |
| 6 | 示例代码 | `example_code` | 完整可运行，覆盖本课全部要点 |
| 7 | 逐行解释 | `code_explanation` | 不少于 5 条，按行号或代码块说明 |
| 8 | 示例输出 | `example_output` | **与真实运行结果一致**（见第五节的一致性测试） |
| 9 | 常见错误 | `common_mistakes` | 4—5 条真实会犯的错 |
| 10 | 错误分析 | `error_analysis` | 报错原文 + 成因 + 修正方向 |
| 11 | 入门练习 | `beginner_exercises` | 照着示例能完成 |
| 12 | 进阶练习 | `advanced_exercises` | 需要组合本课与前面知识 |
| 13 | 本节测验 | `quiz_note` | 说明题目构成与考察重点 |
| 14 | 学习总结 | `summary` | 3—4 句，含一句记忆锚点 |
| 15 | 下一课建议 | `next_lesson` | 指向下一节的具体内容 |

每节课另有 2 个练习（`exercises`，含参考答案与解析）与 6 道测验题（`question_bank`）：
固定 2 道基础理解 + 2 道代码阅读 + 2 道应用练习，六种题型（单选、多选、判断、
代码理解、代码补全、编程思路分析）在两门课里都有实际出现。

## 五、技术版本规范

需求要求「代码写法必须使用对应技术版本的规范」，本阶段的基准与做法：

| 技术 | 教材适用版本 | 体现的规范 |
| --- | --- | --- |
| Python | 3.11+（项目运行于 3.14） | 内置泛型 `list[int]`、`X &#124; None`、`@dataclass`、`match` 之外的现代写法；不用 `typing.List` |
| SQLAlchemy | 2.0.x | `DeclarativeBase`、`Mapped[...]` + `mapped_column()`、`select()` 表达式、`session.scalars()`；**不出现** `declarative_base()` / `session.query()` 这类 1.x 写法 |
| Alembic | 1.x | `revision`/`down_revision` 版本链、`--autogenerate` 后人工校对、SQLite 改列用 `op.batch_alter_table()` |
| SQLite | 3.35+ | 显式 `PRAGMA foreign_keys = ON`、`ON CONFLICT DO NOTHING`、`EXPLAIN QUERY PLAN` 看执行计划 |

自动化保障：
- `test_sqlalchemy_content_uses_2x_style`：ORM 章节必须出现 `DeclarativeBase` / `Mapped[` / `mapped_column(`，
  且不得出现 1.x 旧写法。
- `test_migration_lesson_uses_batch_mode_and_revision_chain`：迁移章节必须出现 `down_revision`、
  `batch_alter_table`、`downgrade`。
- `test_sqlite_lessons_mention_foreign_key_pragma`：SQLite 相关内容必须提到外键开关。

### 这条检查实际抓到的缺陷

| 缺陷 | 现象 | 修正 |
| --- | --- | --- |
| 推导式课时条件写错 | 声明输出 `['写周报']`，实际为空（`len(title) > 3` 与 `minutes > 20` 同时成立的行不存在） | 条件改为 `>= 3` 与 `>= 20`，输出改为两行 |
| SQL 课时 `LIKE '周%'` | 声明输出包含「写周报」，实际匹配不到（该标题以「写」开头） | 改为 `'%周%'` 并同步修正逐行解释 |
| 索引课时造数方式 | `done = index % 2` 与 `user_id = index % 50` 同奇偶，命中行数恒为 0 | 改为 `(index // 7) % 2`，命中行数 43 并写进输出 |
| `PRAGMA index_list` 取列错位 | 打印出序号 `[0]` 而不是索引名 | 改取 `row[1]`，并注明返回五列的含义 |
| 依赖管理课时输出依赖本机 | 声明 `requests 2.32.3`，本机是 2.34.2，任何人跑都对不上 | 改成注入式 `INSTALLED` 映射，输出与机器无关 |
| `ORDER BY ... DESC` 的 NULL 说明 | 注释写「NULL 排最前」，SQLite 实际降序时沉底 | 说明改为「降序沉底、升序置顶」并修正输出顺序 |
