## 一、产品定位

小码是一个帮助编程初学者真正掌握编程知识的 AI 学习教练。

核心学习流程：

学习目标 → 基础诊断 → 学习计划 → 每日任务 → AI 教学 → 测验 → 学习进度更新 → 错题复习 → 动态调整计划。

首发课程为 Python 通用基础。

## 二、固定技术栈

前端：
- Next.js
- TypeScript
- React
- 采用适合当前稳定版本的 App Router 架构

后端：
- Python 3.12
- FastAPI
- SQLAlchemy
- Alembic
- Pydantic

AI：
- LangGraph
- 统一 LLM Provider 接口
- 支持 DeepSeek、通义千问、OpenAI 兼容接口和自定义兼容模型

数据库：
- SQLite
- 不在 V1.0 引入 MySQL、Redis、Celery、ChromaDB

部署：
- Docker Compose

## 三、开发原则

1. 必须从零创建项目，不假设已有代码。
2. 不得一次性生成整个项目，必须按照我给出的开发任务逐步实现。
3. 每个阶段完成后必须运行测试。
4. 修改已有代码前，先检查相关文件。
5. 不得为了完成任务而删除已有功能。
6. 不允许把业务逻辑全部写在 API 路由中。
7. Agent 不允许直接操作数据库，必须通过后端 Service 层。
8. 数据库必须使用 Alembic 管理迁移。
9. 前端必须通过后端 API 获取数据，不允许直接访问数据库。
10. 不得硬编码 API Key、密码和其他秘密信息。
11. 所有重要业务操作必须进行参数校验和异常处理。
12. 不允许用假数据冒充真实业务数据；演示数据必须明确标记。
13. 不允许实现未经产品文档确认的功能。
14. V1.0 不执行用户提交的 Python 代码。
15. 不要擅自引入复杂基础设施或不必要的依赖。

## 四、代码质量要求

- 使用清晰的模块划分。
- 为核心业务逻辑编写自动化测试。
- 关键函数添加类型标注。
- 复杂逻辑添加必要注释。
- API 使用统一响应结构和错误处理。
- 数据库操作考虑事务和数据一致性。
- 不要使用空实现、TODO 或伪代码冒充完成。
- 不允许吞掉异常后返回成功。
- 前后端接口字段保持一致。

## 五、每次任务的执行方式

每次只完成我指定的一个任务。

开始前：
1. 检查当前项目结构。
2. 说明本次要修改或创建哪些文件。
3. 检查是否会影响之前完成的功能。

执行中：
1. 直接完成指定代码。
2. 安装必要依赖。
3. 运行相关检查和测试。
4. 修复本次任务导致的错误。

完成后必须输出：
1. 本次完成的功能。
2. 新建和修改的文件。
3. 执行过的命令。
4. 测试结果。
5. 尚未解决的问题。
6. 我应该如何手动验收。
7. 下一步建议。

如果遇到不明确的产品规则，不要擅自猜测，应先提出问题。

## 六、项目边界

这是一个个人独立部署的开源项目。

V1.0 不开发：
- 多用户 SaaS。
- 社交社区。
- 在线代码执行环境。
- 在线 IDE。
- 付费订阅系统。
- 复杂的企业权限系统。
- 自动长期记忆系统。

初期优先保证单用户学习闭环完整、稳定、可部署。

## 七、重要要求

请把产品文档和本指令作为开发依据。

如果某项实现与产品需求冲突，以产品需求为准，并向我说明冲突，不要自行改变产品方向。
