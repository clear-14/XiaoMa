## 三、每节课的 15 个模块

| # | 模块 | 数据库列 | 写作要求 |
| --- | --- | --- | --- |
| 1 | 学习目标 | `learning_objectives` | 3 条可检验的行为目标，用「会…」开头 |
| 2 | 为什么学 | `why_learn` | 说明不用它会遇到什么麻烦 |
| 3 | 核心概念 | `concept_explanation` | 逐条名词解释，关键术语加粗 |

| 7 | 逐行解释 | `code_explanation` | 至少 3 条，标明行号与作用 |
| 8 | 示例输出 | `example_output` | 与示例代码实际输出一致 |
| 9 | 常见错误 | `common_mistakes` | 列出初学者真实会犯的错误 |
| 10 | 错误分析 | `error_analysis` | 逐条说明报错原因与修正办法 |
| 11 | 入门练习 | `beginner_exercises` | 一步能做完的小任务 |
| 12 | 进阶练习 | `advanced_exercises` | 需要组合本节多个知识点的任务 |
| 13 | 本节测验 | `quiz_note` | 说明本节测验覆盖的知识点与题量 |
| 14 | 学习总结 | `summary` | 回顾本节要点 |

## 四、测验题设计

- 每节课 6 道教材题：2 基础理解 + 2 代码阅读 + 2 应用练习，代码固定为 `q-pb-XX-lNN-N`。
- 另为每章首节补 1 道**多选题**（`q-pb-XX-l01-7`，见 `app/seed/textbook/multi_choice.py`），
  让 6 种题型在课程里都有实际出现，而不是只在代码里"支持"。
- 题目全部带 `knowledge_point_id`（挂在所属课时知识点上）、参考答案与解析；解析说明「为什么」
  而不只是「答案是 B」。
- 客观题按题型给出答案结构：`single_choice` 用 `{"value": "A"}`，
  `multiple_choice` 用 `{"values": ["A","C"]}`，`true_false` 用 `{"value": true}`；
  主观题 `short_answer` / `code_writing` 用 `{"reference": ..., "keywords": [...]}`。
- 新增 `question_bank.category` 列（`基础理解` / `代码阅读` / `应用练习`），使"每节 2/2/2"
  可以被机器核查；历史 93 道内置题在迁移里按题型一次回填。

## 五、内容状态机

```
draft ──▶ reviewed ──▶ published
  ▲           │            │
  └───────────┘            │
              ◀────────────┘
```

- 只允许 `draft → reviewed`、`reviewed → published`、`reviewed → draft`、`published → reviewed`，
  其余跳转返回 409。
- `reviewed → published` 前会重新检查 15 个模块，缺模块或内容过短返回 400 并列出缺失项，
  避免空内容被发布。
- 读取接口默认不返回 `draft` 内容（404），需要显式 `include_draft=true` 才返回，
  未完成内容不会被学习者在正常路径上看到。
- 本次种子统一写入 `reviewed`，**没有**直接把内容标成 `published`，等人工终审。

## 六、内容验收：10 项确定性检查

`GET /api/v1/courses/python-basics/textbook/audit`，规则全部是确定性判断（字段、长度、
关联、关键词、相似度），不依赖模型判断，结论可复现。

| # | 检查 | 通过标准 |
| --- | --- | --- |
| 1 | 20 个章节存在且顺序连续 | 20 章，`order_index` 为 1..20 |
| 2 | 每个章节都有完整课时 | 每章至少 1 节，标题/时长/难度齐全 |
| 3 | 教材内容 15 个模块齐全 | 模块非空且不少于最小长度（示例输出 2 字，其余 10 字） |
| 4 | 代码示例、输出与逐行解释完整 | 示例含输出语句、有示例输出、逐行解释 ≥3 条 |
| 5 | 通俗解释适合初学者 | ≥60 字、不等于核心概念、平均句长 ≤80 字 |
| 6 | 练习已关联对应知识点 | 每节 ≥2 个练习，且都挂在本科时知识点上 |
| 7 | 测验题题量、分类、题型、关联与解析合规 | 每节 ≥6 题、2/2/2 分类达标、6 种题型齐全、有解析、难度不跨两级 |
| 8 | 不提前使用未学习的语法 | 按章节顺序检查示例代码与语法说明（f-string→第 4 章，for→10，while→11，def→12，文件→16，JSON→17，异常→18；面向对象/装饰器/生成器/async 全课程禁止） |
| 9 | 课时与题目没有大量重复 | 4 字片段 Jaccard 相似度 ≤50%，题干不重复 |
| 10 | 学习计划可以引用课时知识点 | 知识点有预计时长与掌握标准，且前置关系不与课程顺序倒挂 |

### 审计发现并修掉的问题（说明检查不是走过场）

1. **6 道题的难度高于所在课时**：入门课时里放了 `intermediate` 题。规则改为"允许高一级、
   禁止跨两级"，保留少量有区分度的进阶题。
2. **第 18 章超纲**：异常处理一节出现了 `class MyError(Exception)`，属面向对象内容。
   已重写该节的目标/概念/语法/错误分析，并把相关题目换成"raise 之后同函数内后续语句如何"。
3. **与历史题库撞题干**："创建空集合的正确写法是？"与内置题库完全重复，已改写教材侧题干。
4. **4 道题缺分类**：`code_writing` 题漏了 `category`，已补齐（应用练习）。
5. **全课程没有多选题**：补了 20 道多选，每章 1 道。
6. **前置关系倒挂**：重排章节后有 5 条旧前置边指向课程更后面的知识点，会让学习计划排期直接报错；
   已在种子里按新顺序清理，并写入审计第 10 项，后续再出现会立刻被检查出来。
7. **知识点排序交错**：`order_index` 原本按课时从 1 重排，导致同章两节课的知识点顺序交错，
   学习计划把前置知识点排到了后面；已改为章节内连续编号。

| 学习计划 / 每日任务 / 会话 | 只引用 `knowledge_point_id` | 不受重排影响 |
| 课程先修关系 | 按知识点 code 引用 | code 未改名，关系保持有效 |
| 测验历史 | `quiz_attempts` 存快照 code 与 scope_name | 历史记录不变 |

为什么坚持不改知识点 code：题库题目 code（`q-python-basics-01-01-1`）、课程目录的先修关系
（如 `python-basics-05-04`）都按 code 引用，改名会让这些既有引用全部失效。因此复用的旧知识点
保留原名，只有 29 个新增知识点使用 `python-basics-XX-kNN` 的新命名。
