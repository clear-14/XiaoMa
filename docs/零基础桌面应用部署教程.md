# 小码桌面应用：零基础部署教程

> 面向完全没接触过 Docker、也没写过命令行的人。
> 只要按顺序做，每一步都写清了「敲什么」和「应该看到什么」。
> 适用版本：Xiaoma 1.4.1（安装包 `Xiaoma-Setup-1.4.1.exe`）
> 更新日期：2026-11-09

---

## 0. 先搞清楚你装的是什么

桌面上那个窗口**不是**一个完整的软件，它只是一个「外壳」。真正干活的两部分在别处：

```
┌──────────────────────────────────────────┐
│  Electron 窗口（desktop/）                │  ← 你看到的部分，没有地址栏
│  只做三件事：开窗口、拉服务、等就绪         │
└──────────────────┬───────────────────────┘
                   │ 加载 http://127.0.0.1:3000
┌──────────────────▼───────────────────────┐
│  Next.js 前端容器（xiaoma-frontend）       │
└──────────────────┬───────────────────────┘
                   │ 同源代理 /api/v1
┌──────────────────▼───────────────────────┐
│  FastAPI 后端容器（xiaoma-backend）        │
│  + SQLite 数据库（存在 Docker 数据卷里）    │
└──────────────────────────────────────────┘
```

这意味着两件很重要的事，先说在前面：

1. **必须装 Docker Desktop。** 没有 Docker，窗口打开后只会停在一个「正在连接本地服务…」的状态页，永远不会进工作台。
2. **关窗口不等于关服务。** 容器会继续在后台跑，下次打开窗口 2 秒就能进。想彻底停掉要手动执行 `docker compose stop`。

## 1. 前置条件

### 1.1 硬件与系统

| 项目 | 要求 | 怎么确认 |
|---|---|---|
| 操作系统 | Windows 10 64 位（2004 及以上）或 Windows 11 | 设置 → 系统 → 关于 |
| 内存 | 至少 8 GB，建议 16 GB | 任务管理器 → 性能 |
| 磁盘 | 至少 10 GB 空闲 | 资源管理器看 C 盘 |
| 虚拟化 | BIOS 里必须开启 | Docker Desktop 启动时会检查并提示 |

### 1.2 必须装的两样东西

| 软件 | 用途 | 是否必装 |
|---|---|---|
| **Docker Desktop** | 跑前后端服务，桌面版的命根子 | 必装 |
| Node.js 22 或更高 | 只有「从源码运行」和「自己打包」时才需要 | 可选 |

> 如果你只想**用**这个软件，不打算改代码，那 Node.js 可以不装，直接跳到第 2 节。

## 2. 路线 A：装安装包（推荐，全程不敲命令）

这条路适合 95% 的人。全程只有三步：装 Docker → 装小码 → 双击图标。

### 第 1 步：安装 Docker Desktop

1. 打开 <https://www.docker.com/products/docker-desktop/> 下载 Windows 版。
2. 双击下载的 `Docker Desktop Installer.exe`，一路「Next」，**保持勾选 "Use WSL 2 instead of Hyper-V"**。
3. 安装完成后**重启电脑**（不重启大概率起不来）。
4. 从开始菜单启动 Docker Desktop，等左下角状态变成绿色的 **Engine running**。

验证一下。按 `Win + R`，输入 `powershell` 回车，然后粘贴：

```powershell
docker --version
docker compose version
```

应该看到类似输出（版本号不必完全一致）：

```
Docker version 27.3.1, build ce12230
Docker Compose version v2.29.7
```

如果提示 `docker: 无法将"docker"项识别为...`，说明装完没重启，或者 Docker Desktop 没启动。回去做第 3、4 步。

> **国内网络提示**：首次启动要拉取镜像，如果卡在 `pulling` 很久不动，给 Docker Desktop 配一个镜像加速器（设置 → Docker Engine，在 JSON 里加 `registry-mirrors`），然后 Apply & Restart。

### 第 2 步：安装小码

1. 拿到安装包 `Xiaoma-Setup-1.4.1.exe`（约 117 MB）：优先从 <https://github.com/clear-14/XiaoMa/releases> 下载，或由发布者直接发给你。**从 GitHub 克隆下来的仓库里没有这个文件**（`desktop/dist/` 是构建产物，已被忽略），不要在项目目录里找它。如果 Releases 页面还没有资产，先跳到第 4 节「路线 C：自己打包 exe」生成安装包，再回到这里继续第 2 步。
2. 双击运行。Windows 会弹 **"Windows 已保护你的电脑"**，因为安装包没做代码签名——这不是病毒，点 **更多信息 → 仍要运行**。
3. 选择安装目录，默认是 `C:\Users\<你的用户名>\AppData\Local\Programs\Xiaoma`，直接下一步即可。
4. 安装器会自动创建桌面快捷方式和开始菜单项。

**想静默安装（不弹任何界面）**，用 PowerShell：

```powershell
.\Xiaoma-Setup-1.4.1.exe /S
```

> 在 Git Bash 里要写成 `//S`，否则 `/S` 会被当成路径转换掉。

### 第 3 步：第一次启动，耐心等

双击桌面上的 **Xiaoma** 图标。会依次看到：

| 阶段 | 窗口显示 | 大约耗时 |
|---|---|---|
| 1 | 「正在连接本地服务…」 | 1–3 秒 |
| 2 | 「正在构建并启动本地服务容器…」 | 首次 60–90 秒（实测 87 秒） |
| 3 | 界面上出现「首页 / 学习计划 / 课程学习 …」 | 完成 |

**首次启动慢是正常的**，它在构建前后端两个 Docker 镜像。第二次以后启动只要 2 秒左右，因为窗口会先探活，发现服务已经在跑就直接复用。

如果超过 **120 秒**还停在状态页，看第 6 节的故障表。

### 第 4 步：配置 AI 模型（否则对话功能用不了）

窗口能进去不代表能聊天。工作台需要一个大模型，第一次用必须配一次：

1. 左侧导航 → **系统设置** → 模型配置。
2. 添加一个模型，例如：
   - 服务商：`DeepSeek`
   - 模型名：`deepseek-chat`
   - API Key：去 <https://platform.deepseek.com> 注册后生成，形如 `sk-xxxxxxxx`
3. 保存并**设为默认**。
4. 左侧导航 → **AI 学习工作台**，发一句「你好」测试。

Key 会用 Fernet 加密后存进数据库，页面上只显示 `sk-****abcd` 这样的脱敏值，日志里也不会记录明文。

## 3. 路线 B：从源码运行（要改代码时用）

改前端界面、改后端逻辑，都必须走这条路。因为安装包里打包的是**构建时的快照**，你改了源码它不会变。

### 3.1 装 Node.js

去 <https://nodejs.org> 下载 LTS 版（22 或更高），一路下一步。装完验证：

```bash
node -v      # 应输出 v22.x 或更高
npm -v
```

### 3.2 装桌面端依赖

```bash
cd D:/XiaoMa/desktop
npm install
```

只装两个包（electron 45.2.3、electron-builder 26.18.0），大约 2–3 分钟。

### 3.3 启动窗口

```bash
cd D:/XiaoMa/desktop
npm run dev
```

窗口出现后，逻辑和安装版完全一样：先探活 `http://127.0.0.1:3000`，通了直接进工作台，不通就自己去 `docker compose up -d --build`。

### 3.4 一个很容易踩的坑

如果你在**别的程序里**（比如某些 IDE 的集成终端、自动化脚本环境）启动，可能会看到这样的报错：

```
TypeError: Cannot read properties of undefined (reading 'requestSingleInstanceLock')
    at Object.<anonymous> (D:\XiaoMa\desktop\src\main.js:376:10)
```

**原因**：环境里存在 `ELECTRON_RUN_AS_NODE=1`，Electron 被当成纯 Node.js 运行了，`app` 对象根本不存在。

**解决**：启动前清掉这个变量。

PowerShell：

```powershell
Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
Remove-Item Env:NODE_OPTIONS -ErrorAction SilentlyContinue
npm run dev
```

Git Bash：

```bash
unset ELECTRON_RUN_AS_NODE
unset NODE_OPTIONS
npm run dev
```

用系统自带的 PowerShell / CMD 直接 `npm run dev` 一般不会遇到这个问题。

### 3.5 开发时的正确姿势

如果你希望**改代码立刻生效**，不要用桌面窗口，直接用浏览器：

```bash
# 终端 1：后端
cd D:/XiaoMa/backend
.venv/Scripts/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload

# 终端 2：前端
cd D:/XiaoMa/frontend
npm run dev
```

然后浏览器打开 <http://127.0.0.1:3000>。桌面窗口加载的就是这个地址，所以两边看到的内容完全一样，只是浏览器有地址栏、改完立即热更新，调试更方便。

## 4. 路线 C：自己打包 exe

想把改动做成一个能发给别人的安装包，走这条。

### 4.1 打包前三项检查（别跳）

```bash
cd D:/XiaoMa/desktop
npm run check     # 语法检查 7 个文件
npm test          # 服务控制器 / preload 防护 / 无 shell 调用 三组单测
```

`npm run check` 会逐个 `node --check` 主进程、preload、菜单、状态页渲染等文件；`npm test` 覆盖启动状态机、命令白名单、安全边界。这两条不通过就别打包，打出来也是坏的。

### 4.2 执行打包

```bash
cd D:/XiaoMa/desktop
npm run dist:win
```

耗时 3–6 分钟。产物落在 `desktop/dist/Xiaoma-Setup-1.4.1.exe`，名字里的版本号取自 `package.json` 的 `version`。

### 4.3 打包时到底装进去了什么

`npm run dist:win` 会先跑 `scripts/stage-project.js` 这个钩子，把 Compose 工程**按白名单**复制到 `build-staging/project`，再塞进安装包的 `resources/project` 目录：

| 会被打进安装包 | 不会被放进安装包（重要） |
|---|---|
| `docker-compose.yml` | `.env`（可能含密码） |
| `.env.example` | `data/`（数据库） |
| `backend/`（去掉缓存与虚拟环境） | `.venv/`、`node_modules/` |
| `frontend/`（去掉 `.next` 构建产物） | `.next/`、`dist/`、`.git/` |
| — | `tests/`、`*.db`、`.secret_key`、`*.log` |

这条边界不是随手写的：数据库和密钥属于用户隐私，虚拟环境和 `node_modules` 会让镜像层失效（几万个文件的哈希每次都变）。所以你**不要**试图手动把 `data/xiaoma.db` 塞进安装包——装到别人机器上也起不来，路径和密钥都对不上。

### 4.4 打包失败常见原因

| 现象 | 原因 | 处理 |
|---|---|---|
| `批量删除被安全策略拦截` 警告 | 终端的安全删除策略拦了 `rmSync` | 脚本会自动重命名归档并继续，不用管；想清理就手动删 `build-staging/project-stale-*` |
| `打包缺少必要文件：docker-compose.yml` | 在 `desktop/` 之外执行了打包 | 必须在 `desktop` 目录下执行 |
| 杀毒软件报毒 | 未签名的 Electron 应用常见误报 | 加白名单，或后续购买代码签名证书 |

## 5. 窗口怎么用

### 5.1 菜单与快捷键

窗口没有地址栏，所有运维动作都放在菜单里：

| 菜单项 | 快捷键 | 什么时候用 |
|---|---|---|
| 文件 → 选择项目目录… | `Ctrl + ,` | 提示「未找到 docker-compose.yml」时，手动指定仓库根目录 |
| 文件 → 重新检测本地服务 | `Ctrl + Shift + R` | 状态页卡住、刚启动完 Docker Desktop 之后 |
| 文件 → 退出 | `Ctrl + Q` | 关窗口（服务不停） |

「选择项目目录」的地址会记在 `%APPDATA%\xiaoma-desktop\config.json` 里，下次不用重选。

### 5.2 窗口会记住位置和大小

拖过、拉过、最大化过，下次打开还原到上次的样子。数据存在 `%APPDATA%\xiaoma-desktop\window-state.json`。多显示器拔掉后窗口跑到屏幕外的话，删掉这个文件即可复位。

### 5.3 只允许开一个窗口

再次双击图标不会开第二个，而是把已有窗口提到前台。

## 6. 状态页故障速查

窗口启动失败时不会给你看浏览器错误页，而是显示一个中文状态页，上面有错误码和「重试」按钮。对照下表：

| 页面提示 | 真实原因 | 处理 |
|---|---|---|
| 未检测到运行中的 Docker Desktop | Docker 没启动，或刚装完没重启 | 启动 Docker Desktop，等 Engine running，点「重试」 |
| 本地服务尚未响应，数据库迁移可能需要 30–90 秒 | 还在宽限期内，正常现象 | 等，最多 120 秒 |
| 本地服务启动超时 | 超过 120 秒仍未就绪 | 打开 Docker Desktop 看容器日志；执行 `docker compose logs backend --tail 50` |
| 未找到 docker-compose.yml | 项目目录不对 | `Ctrl + ,` 选择仓库根目录（含 `docker-compose.yml` 的那层） |
| Docker 拒绝了本次操作 | 账号权限不足 | 用管理员身份运行，或把用户加入 `docker-users` 组后重新登录 |
| 界面加载失败 | 前端容器挂了 | `docker compose ps` 看 `xiaoma-frontend` 是否 healthy |

### 6.1 万能的排查三连

在项目根目录执行：

```bash
docker compose ps                          # 两个容器是否 Up / healthy
docker compose logs backend --tail 50      # 后端启动日志
curl http://127.0.0.1:3000/api/v1/health   # 应返回 {"status":"ok","version":"..."}
```

三条都通过，窗口一定能进。

### 6.2 端口被占用

桌面版固定使用 `3000`（前端）和容器内的 `8000`（后端，不映射到宿主机）。如果 3000 被别的程序占了：

```bash
netstat -ano | findstr :3000
```

记下 PID，去任务管理器结束它。最常见的占用者就是上一次没关干净的 Docker 容器：

```bash
docker compose down
```

## 7. 数据存在哪里

| 内容 | 位置 | 说明 |
|---|---|---|
| 学习数据（课程、进度、对话、错题） | Docker 命名卷 | 在容器内 `/app/data/xiaoma.db`，**不在你的项目目录里** |
| 模型 API Key 加密密钥 | 同上，`/app/data/.secret_key` | 首次启动自动生成，丢了 Key 就无法解密 |
| 窗口位置/大小、项目目录 | `%APPDATA%\xiaoma-desktop\` | 删了只是丢窗口设置 |
| 程序本体 | `%LOCALAPPDATA%\Programs\Xiaoma\` | 卸载会删这里 |

### 备份数据

窗口内：**系统设置 → 数据备份 → 立即备份**，可下载 `.db` 文件。

命令行：

```bash
docker compose exec backend python -m app.cli backup-db
```

用的是 SQLite 在线备份 API，服务运行中执行也安全，不会备份到一半的数据。

### 恢复数据

必须先停后端，再恢复：

```bash
docker compose stop backend
docker compose exec backend python -m app.cli restore-db <备份文件名> --yes
docker compose start backend
```

恢复前系统会自动把当前库备份成 `pre-restore-*.db`，校验失败不会覆盖现有数据。

## 8. 卸载与彻底清理

### 8.1 正常卸载

**推荐用 PowerShell**：

```powershell
Start-Process "$env:LOCALAPPDATA\Programs\Xiaoma\Uninstall Xiaoma.exe" -ArgumentList "/S" -Wait
```

> **别在 Git Bash 里卸**。`"Uninstall Xiaoma.exe" //S` 会出现「退出码 0 但一个文件都没删」的假成功，实测必须换 PowerShell。

### 8.2 卸载之后还剩什么

卸载**不会**清理这两样东西，这是故意的，方便你重装后接着用：

- `%APPDATA%\xiaoma-desktop`（窗口设置）
- Docker 容器与数据卷（你的全部学习数据）

### 8.3 彻底清除（数据会没，先备份）

```bash
# 1. 先备份！备份文件会被一起删掉，记得下载到别处
docker compose exec backend python -m app.cli backup-db

# 2. 删容器 + 数据卷（数据库一并消失）
docker compose down -v

# 3. 删窗口配置
rm -rf "$APPDATA/xiaoma-desktop"
```

第 2 步是不可逆的。执行前确认备份文件已经拷到别的地方。

## 10. 一分钟速查卡

```bash
# 装依赖（只需一次）
cd D:/XiaoMa/desktop && npm install

# 开窗口
cd D:/XiaoMa/desktop && npm run dev

# 打包成安装包
cd D:/XiaoMa/desktop && npm run check && npm test && npm run dist:win

# 看服务状态
docker compose ps

# 看后端日志
docker compose logs backend --tail 50

# 健康检查（最关键的一条）
curl http://127.0.0.1:3000/api/v1/health

# 停服务（窗口关了服务还在，用这个停）
docker compose stop
```

**记住一件事**：窗口本身不承载任何业务逻辑，它只是一个加载器。任何界面异常，先查 `curl http://127.0.0.1:3000/api/v1/health` 通不通——通了就是界面问题，不通就是 Docker 问题，排查范围立刻缩小一半。
