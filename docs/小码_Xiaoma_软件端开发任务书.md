# 小码 Xiaoma V1.4 — Codex 前端改造任务书

## 总规则
以《小码 Xiaoma PRD V1.4》为最新产品交互依据。保留 V1.3 已确定的业务功能和技术架构，不得因为界面调整而删除学习计划、课程、测验、错题、学习档案等功能。当前项目尚未开始编码，本任务书指导从零构建，不假设已有前端代码。

## 阶段 1：项目结构和技术方案
先阅读 PRD V1.4。输出：
1. 前端页面结构。
2. 前端组件结构。
3. 路由设计。
4. 对话消息数据结构。
5. 卡片消息数据结构。
6. 前后端 API 通信方案。
7. 响应式布局方案。
本阶段只做技术设计，不要开始业务代码。

## 阶段 2：前端工程初始化
使用 Next.js、TypeScript、React、App Router 创建基础工程。
要求：
1. 建立统一 Layout。
2. 建立全局样式和设计变量。
3. 建立 API 请求封装。
4. 建立错误处理机制。
5. 建立 Loading、Empty、Error 通用组件。
6. 建立前端环境变量配置。
7. 配置代码检查和基础测试。
验收：前端可以启动；首页可以打开；页面无明显控制台错误。

## 阶段 3：三栏式工作台 UI
实现左侧导航栏、中间 AI 对话区域、右侧学习工作区。
要求：
- 左侧导航支持展开和收起。
- 中间对话区占据主要宽度。
- 右侧学习面板支持展开和收起。
- 输入框固定在对话区域底部。
- 内容区域独立滚动。
- 支持桌面和移动端。
- 移动端通过抽屉打开导航和学习面板。
本阶段只实现布局和空状态，不允许用虚构数据冒充真实数据。

## 阶段 4：会话管理和聊天历史
实现新建对话、会话列表、会话标题、重命名、删除、恢复历史会话、消息列表和消息持久化接口对接。
要求：
- 每个会话有独立 ID。
- 新会话不能覆盖旧会话。
- 删除会话前确认。
- 删除聊天不能删除独立学习业务数据。

## 阶段 5：对话消息与卡片协议
建立统一消息渲染系统。
消息类型：text、task_card、lesson_card、quiz_card、quiz_result_card、mistake_card、plan_card、plan_change_card、progress_card、error_card。
要求：
- 使用 TypeScript 类型定义。
- structured_data 必须经过校验。
- 支持消息协议版本。
- 未识别类型有安全的降级展示。
- 卡片数据不能由前端从普通文本猜测。
- 历史消息能够恢复卡片。
- 流式输出未完成时不能渲染不完整卡片。

## 阶段 6：AI 对话与流式输出
实现用户发送消息、后端 API 对接、AI 流式输出、停止生成、错误提示、普通回复重新生成、复制消息和会话上下文加载。
要求：
- 模型没有配置时提示用户设置。
- 模型超时不能无限等待。
- 不能伪造 AI 回复。
- 用户消息和 AI 消息都要持久化。
- 页面刷新后可以恢复会话。

## 阶段 7：学习工作区
实现右侧四个面板：当前学习计划、今日学习任务、当前知识点、学习进度。
数据全部通过后端 API 获取。
要求：
- 展示加载状态、空状态和接口错误。
- 数据更新后刷新对应区域。
- 不允许前端自行计算或伪造知识点掌握状态。

## 阶段 8：学习交互卡片
依次实现：
1. 今日任务卡片。
2. 知识点讲解卡片。
3. 测验题目卡片。
4. 测验结果卡片。
5. 错题复习卡片。
6. 学习计划卡片。
7. 计划调整确认卡片。
8. 学习进度卡片。

每个卡片必须有明确数据类型、真实数据来源、明确交互行为，调用对应后端 API，有成功、失败和加载状态，并且刷新后能够恢复。计划调整必须由用户确认后才正式保存。

## 阶段 9：后端对话与 Agent 集成
使用 FastAPI + LangGraph。
要求：
- 对话 API 负责会话处理。
- LangGraph 负责工作流编排。
- Agent 工具通过 Service 层调用业务。
- Agent 不允许直接操作数据库。
- 对话流支持文本和结构化事件。
- 工具失败要返回可识别错误。
- 重要业务操作必须经过后端校验。

## 阶段 10：端到端验收
完成以下测试：
1. 新建对话。
2. 发送消息并接收流式回复。
3. 刷新后恢复对话。
4. 查看今日学习任务。
5. 查看当前学习计划。
6. 让 AI 讲解一个知识点。
7. 在对话中完成测验。
8. 查看测验结果。
9. 查看错题并复习。
10. 请求调整学习计划并确认。
11. 查看学习进度。
12. 切换模型。
13. 测试模型不可用时的错误提示。
14. 测试移动端布局。

每个阶段完成后必须提供测试报告，未通过的项目先修复，不得直接进入下一阶段。

## 特别约束
- 不执行用户提交的 Python 代码。
- 不擅自增加 SaaS、多用户、在线 IDE 等功能。
- 不引入 MySQL、Redis、Celery、ChromaDB。
- 不用模拟数据代替真实业务接口。
- 不允许只完成 UI 外观而没有实际交互。
- 不允许把所有业务逻辑写在前端。
- 不允许让 AI 回复直接决定数据库中的学习状态。
