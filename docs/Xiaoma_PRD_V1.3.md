# 1. 产品概述与定位
小码（Xiaoma）是一款开源、免费、面向编程新手的 AI 编程学习教练。产品不以单纯聊天为目标，而是围绕用户的学习目标和实际掌握情况，组织课程、学习计划、每日任务、AI 教学、测验、错题复习和动态调整。
## 1.1 核心价值
不只是告诉用户“应该学什么”，而是通过结构化课程和持续验证，帮助用户逐步真正掌握编程知识。
## 1.2 核心学习闭环
学习目标 → 基础诊断 → 学习计划 → 每日任务 → AI 教学 → 测验 → 学习进度更新 → 错题复习 → 动态调整学习计划。
## 1.3 产品形态
个人单用户独立部署，用户拥有自己的数据。
开源、免费，面向个人学习者。
优先支持本机运行，支持用户自行配置兼容模型。
首发课程为 Python 通用基础，后续扩展 Python 数据分析等方向。

# 3. 产品目标、原则与范围
## 3.1 产品目标
让用户能够建立清晰、可执行的个人学习计划。
每天打开首页即可获得适合当前进度的学习任务。
让 AI 结合用户学习档案和当前知识点开展教学。
通过测验和复习记录验证知识点掌握情况。
保留聊天历史、学习档案和学习过程数据。
提供可在个人设备或服务器独立部署的完整产品。
## 3.2 产品原则（必须遵守）
学习结果优先于聊天数量。
课程体系由结构化课程数据维护，AI 不得随意创造正式课程结构。
用户报告完成与系统验证掌握必须区分。
测验范围不得超出用户已经学习的内容。
AI 负责理解、讲解、建议和生成；后端负责业务规则、状态校验和数据写入。
用户数据默认保存在用户自己的部署环境中。
先保证稳定、易部署和核心闭环，再扩展复杂能力。
## 3.3 V1.0 范围
单用户个人独立部署。
Python 通用基础课程。
学习档案、基础诊断、结构化课程、学习计划和每日任务。
AI 教学与聊天历史。
题库、测验、评分、错题本和复习任务。
LangGraph 学习 Agent 工作流。
模型配置、切换、连接测试及流式输出。
SQLite 数据持久化、备份恢复和 Docker Compose 部署。
## 3.4 V1.0 明确不包含
多用户 SaaS、社交社区和企业权限体系。
在线代码执行环境、在线 IDE。
付费订阅系统。
自动长期记忆系统。
完整就业能力评估。
首版以外的多语言课程体系。
# 4. 核心业务流程
## 4.1 首次使用流程
首次启动 → 初始化个人学习档案 → 设置学习目标和每日学习时间 → 完成基础诊断 → 生成学习计划 → 用户确认计划 → 进入首页。
## 4.2 每日学习流程
打开首页 → 查询当天任务 → 如已有任务则展示；如无任务则根据学习计划和进度生成 → 用户开始学习 → AI 讲解 → 用户完成任务 → 根据测验验证掌握情况。
## 4.3 测验与复习流程
选择测验范围 → 系统读取已学知识点和学习进度 → 从审核题库选择或生成经过验证的变式题 → 用户答题 → 后端评分并保存 → 更新掌握状态 → 记录错题并安排复习。
## 4.4 计划调整流程
读取当前计划、任务完成情况和测验结果 → AI 提出调整建议 → 用户确认 → 创建新计划版本 → 保留历史计划、已完成任务和学习记录。

支持单选、多选、判断、填空、简答、代码分析、代码编写和项目类题型。V1.0 的代码题仅进行文本分析，不执行用户代码。
## 6.3 题目来源与质量控制
核心题目来自人工审核的内置题库。
AI 可以生成变式题，但必须经过自动验证。
验证内容包括题目格式、答案、解释、知识点归属和学习范围。
验证失败的题目不得进入正式测验。
测验前必须读取用户学习计划、已学和已掌握知识点、近期测验结果、薄弱点及本次测验范围。
不得对尚未学习的知识点进行正式测验。
## 6.4 评分与掌握判定
不同题型采用对应评分规则。
主观题应保留评分依据和解释。
90 分可作为参考，不是适用于所有题型的统一掌握阈值。
掌握状态由后端依据明确规则更新，不能只根据一次普通聊天判断。
## 6.5 错题与间隔复习
建议复习间隔为 1、3、7、14 天。答错时可以缩短复习间隔。系统应记录错题所属知识点、尝试次数、最近答题结果和复习状态。

## 7.3 异常与可靠性

失败时返回明确错误状态和可理解提示，不得无限等待。
工具调用失败不得伪装成成功。
关键业务数据以数据库和后端校验结果为准，不以模型自由生成内容为准。

# 11. 安全、隐私与部署
## 11.1 访问控制
默认仅允许本机访问。
如启用局域网或公网访问，必须要求访问密码。
访问保护必须在后端执行，不能只依赖前端页面隐藏。
公网部署时应配置 HTTPS，并遵循安全部署说明。
## 11.2 数据和密钥保护
SQLite 数据文件使用持久化卷保存。
模型 API Key 加密存储，页面脱敏展示。
日志不得记录完整密钥。
.env 文件不得提交到 GitHub。
用户数据不上传到开发者中心化服务器。
应向用户说明：模型提示词、必要上下文及搜索查询可能发送给用户配置的第三方模型或服务提供商。
## 11.3 部署交付
目标部署流程：
git clone https://github.com/<your-username>/xiaoma.git
cd xiaoma
cp .env.example .env
docker compose up -d
首次打开本地页面后，用户初始化学习档案、配置模型并开始学习。项目应提供中文和英文 README、安装说明、Docker 部署、模型配置、安全、备份恢复、FAQ、开发指南、许可证和更新日志。
