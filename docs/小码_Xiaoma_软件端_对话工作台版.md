# 小码 Xiaoma 产品需求文档 PRD V1.4
## 对话框 + 学习工作区版本

版本状态：交互方向已确认，进入技术设计与开发准备阶段
产品定位：开源、免费、个人独立部署的 AI 编程学习教练
首发课程：Python 通用基础
产品形态：AI 对话主界面 + 学习工作区

# 1. V1.4 版本说明
V1.4 在 V1.3 已确认的产品定位、学习闭环、业务规则和技术选型基础上，重新设计产品交互方式。

本次主要变化：
1. 将 AI 对话框升级为产品的核心入口。
2. 将原来的 Dashboard 改为对话式学习首页。
3. 增加左侧导航与历史会话区域。
4. 增加右侧学习上下文工作区。
5. 将学习任务、课程、测验、错题和计划调整整合到对话交互中。
6. 将重要业务结果以结构化卡片呈现，而不是只返回文字。
7. 保留学习档案、结构化课程、题库、错题和学习计划等原有业务能力。

V1.3 中已经确认的产品功能和业务规则继续有效；如与本版本交互设计存在冲突，以 V1.4 的界面交互规定为准。

# 2. 产品定位
小码是一款帮助编程初学者系统学习编程知识的 AI 学习教练。用户通过自然语言与 AI 交流，AI 根据用户的学习目标、课程进度和掌握情况，提供讲解、练习、测验和复习。

产品不是普通聊天机器人，也不是在线 IDE，而是一个具备学习记忆、任务管理、知识体系和学习效果验证能力的对话式学习工作台。

核心理念：
- 对话是主要入口。
- 学习任务是主要行动。
- 结构化课程是知识基础。
- 测验是掌握验证手段。
- 学习档案是个性化依据。
- 后端业务服务保证数据真实可靠。

# 3. 产品整体布局
采用桌面端优先、兼容移动端的三栏式布局。

## 3.1 左侧导航栏
主要职责：管理功能入口和历史对话。

包含：
- 小码 Logo 和产品名称。
- 新建对话。
- 首页 / 学习工作台。
- 学习计划。
- 课程体系。
- 测验记录。
- 错题本。
- 学习档案。
- 系统设置。
- 最近会话列表。

交互要求：
1. 支持收起和展开。
2. 新建对话后创建独立会话。
3. 历史会话按照最近活动时间排序。
4. 点击历史会话能够恢复完整聊天记录。
5. 支持会话重命名和删除。
6. 删除会话前需要二次确认。
7. 删除聊天会话不能删除学习计划、测验记录等独立业务数据。

## 3.2 中间 AI 对话区
主要职责：完成绝大部分学习交互。

包含：
- 当前会话标题。
- AI 回复区域。
- 用户消息区域。
- 流式回复状态。
- 学习任务卡片。
- 知识点讲解卡片。
- 测验交互卡片。
- 测验结果卡片。
- 错题复习卡片。
- 学习计划调整确认卡片。
- 底部消息输入框。

输入框要求：
- 支持多行输入。
- Enter 发送，Shift + Enter 换行。
- 支持停止生成。
- 支持重新生成（适用于普通 AI 回复）。
- 支持复制回答。
- 支持清空输入。
- 未配置模型时显示配置提示。
- 模型异常时显示明确错误状态。

对话区必须支持流式输出，不能在模型尚未完成时伪装为完整回复。

## 3.3 右侧学习工作区
主要职责：显示当前学习上下文，避免用户在对话和学习状态之间来回切换。

包含四个主要区域：

### A. 当前学习计划
显示：当前课程、当前学习阶段、计划完成进度、当前章节、下一步学习目标。

### B. 今日学习任务
显示：任务标题、关联知识点、预计学习时间、任务状态、开始学习入口、完成状态。

### C. 当前知识点
显示：知识点名称、学习目标、难度、前置知识点、掌握状态、学习资源。

### D. 学习进度
显示：已掌握知识点数量、正在学习知识点数量、待验证知识点数量、当前薄弱知识点、最近测验结果。

交互要求：
1. 右侧面板支持展开和收起。
2. 支持切换查看计划、任务、知识点和进度。
3. 面板内容根据当前对话上下文更新。
4. 面板展示的数据必须来自后端真实业务数据。
5. 不允许由前端根据聊天文字自行推断掌握状态。
6. 移动端改为抽屉或底部面板，不强制保持三栏布局。

# 4. 首页与首次使用流程
## 4.1 首次启动
1. 展示简洁欢迎页。
2. 初始化学习档案。
3. 设置学习目标。
4. 选择当前编程基础。
5. 设置每天可学习时间。
6. 完成基础诊断。
7. AI 提出学习计划。
8. 用户确认后保存正式计划。
9. 进入对话式学习工作台。

## 4.2 非首次启动
1. 恢复最近使用的工作区。
2. 读取学习档案。
3. 获取当天任务。
4. 如果当天任务不存在，按既定规则生成。
5. 在对话欢迎区域展示今日学习建议。
6. 右侧面板同步显示当前计划和任务。

每日任务的查询与生成必须由后端业务服务保证幂等，不能由前端每次打开页面都重复创建。

# 5. 对话式学习交互
## 5.1 普通教学对话
用户：“我是零基础，给我讲讲 Python 的变量。”
AI 应当读取必要的学习档案和当前学习上下文，判断用户基础，讲解变量含义，给出简单示例并解释关键部分，提供小练习，再询问用户是否理解，必要时继续讲解。

## 5.2 今日任务交互
用户：“今天应该学什么？”
AI 应展示今日任务卡片，包含今日学习主题、关联知识点、学习目标、预计时长、开始学习操作，以及完成后进入测验的入口。

## 5.3 学习计划交互
用户：“我每天只能学习 30 分钟，帮我调整计划。”
AI 读取当前计划、分析学习进度、生成调整建议、展示调整前后差异并等待用户确认。确认后调用后端 Service 保存新版本并返回结果。未经用户确认不得修改正式学习计划。

## 5.4 测验交互
用户：“测试一下我对变量的掌握程度。”
AI 获取已学习知识点并校验测验范围，从审核题库选题或生成并验证变式题，以交互题目卡片展示。用户提交答案后由后端评分，展示得分、正确答案和解析，并更新知识点状态和错题记录。不能只通过 AI 自由对话判断测验结果。

## 5.5 错题复习交互
用户：“带我复习昨天做错的题。”
AI 查询真实错题记录，按知识点组织复习，展示错题和原始答案，允许重新作答，反馈解析，更新复习记录，并按复习规则安排下一次复习。

## 5.6 学习进度交互
用户：“我现在学到哪里了？”
AI 读取后端数据并返回当前课程和章节、已掌握知识点、正在学习知识点、待验证知识点、薄弱知识点和推荐下一步学习内容。所有数字必须与后端数据一致。

# 6. 对话消息与交互卡片
建议消息类型：
- text：普通文本。
- task_card：学习任务。
- lesson_card：知识点讲解。
- quiz_card：测验题目。
- quiz_result_card：测验结果。
- mistake_card：错题复习。
- plan_card：学习计划。
- plan_change_card：计划调整建议。
- progress_card：学习进度。
- error_card：操作失败或异常提示。

原则：
1. 卡片展示数据来自后端业务结果。
2. 卡片按钮必须调用真实 API。
3. 重要修改操作必须有确认步骤。
4. 卡片失败时明确展示失败状态。
5. 刷新页面后历史消息和卡片内容应可恢复。
6. 不能只保存卡片渲染结果，应保存必要的结构化消息数据。

# 7. 页面清单
1. 首次初始化页面。
2. 对话式学习工作台。
3. 学习计划详情页。
4. 课程与知识点页面。
5. 测验记录页面。
6. 错题本页面。
7. 学习档案页面。
8. 系统设置页面。

对话式学习工作台是默认首页。其他页面是对话工作台的辅助功能，不应反过来成为用户学习的主要入口。

# 8. 视觉和交互要求
整体风格：简洁、现代、轻量；参考 Codex 类 AI 工作台的布局逻辑，不直接复制其他产品品牌设计；以阅读和持续对话为核心；控制卡片数量和视觉干扰；重点信息清晰，次要信息可折叠。浅色和深色主题可作为后续增强，不阻塞首版。

桌面端：左侧导航栏宽度适中且可收起；中间对话区占主要宽度；右侧学习面板可收起；输入框固定在对话区底部；长内容在对话区内部滚动。

移动端：默认只显示对话区；左侧导航通过抽屉打开；学习工作区通过抽屉或底部面板打开；输入框固定在屏幕底部安全区域内；卡片适配窄屏，不出现横向溢出。

# 9. 原有业务功能继续保留
V1.3 以下功能和业务规则不变：
- 单用户个人独立部署。
- Python 通用基础首发课程。
- 学习档案和基础诊断。
- 结构化课程体系。
- 学习计划和版本管理。
- 每日任务查询与幂等生成。
- AI 教学和聊天历史。
- 人工审核题库和 AI 变式题验证。
- 测验、评分、错题和间隔复习。
- 动态学习计划调整。
- 模型配置和多模型兼容。
- SQLite、SQLAlchemy、Alembic。
- FastAPI、LangGraph、Next.js、TypeScript。
- Docker Compose 部署。
- 默认本机访问；开放局域网或公网时必须启用访问密码。
- V1.0 不执行用户提交的 Python 代码。
- 自动长期记忆放入 P1。

# 11. 技术实现约束
前端 Next.js + TypeScript；后端 FastAPI；Agent 使用 LangGraph；数据库使用 SQLite、SQLAlchemy 和 Alembic。新增前端交互不能改变后端业务数据的权威来源。

建议对话消息字段：
- id
- conversation_id
- role
- content
- message_type
- structured_data
- status
- created_at

structured_data 用于保存卡片结构化数据。需要定义类型版本，避免未来卡片协议变化导致旧聊天记录无法展示。流式响应支持文本增量和结构化事件；不能把尚未完成的 JSON 卡片直接当作完整卡片渲染。Agent 通过工具调用后端 Service，不允许直接访问数据库。

# 12. V1.4 验收标准
界面验收：
- 默认打开对话式工作台。
- 左侧导航可展开、收起。
- 历史会话可恢复。
- 中间区域可持续对话。
- 右侧学习面板可展开、收起。
- 移动端布局可正常使用。

功能验收：
- AI 回复能够流式展示。
- 能够展示真实今日任务卡片。
- 能够展示当前学习计划和知识点。
- 能够在对话中完成测验并查看结果。
- 能够在对话中发起错题复习。
- 计划调整需要用户确认。
- 卡片刷新后可以恢复。
- 卡片按钮调用真实业务接口。
- 模型错误和工具错误能够明确反馈。

数据验收：
- 聊天记录与业务数据分离保存。
- 用户完成任务不等于知识点掌握。
- 测验结果以服务端评分为准。
- 学习面板数据与数据库真实记录一致。
- 删除会话不删除独立学习业务数据。

# 13. 产品最终形态
用户打开软件 → 进入 AI 对话工作台 → AI 读取学习上下文 → 展示今日任务 → 用户开始对话学习 → AI 讲解知识点 → 生成练习和测验 → 保存学习记录 → 更新学习档案 → 推荐下一步任务。

产品最终应让用户感觉：“我不需要先研究一套复杂的学习管理系统。我只要打开小码，就能知道今天学什么，并且可以直接和 AI 一起完成学习。”
