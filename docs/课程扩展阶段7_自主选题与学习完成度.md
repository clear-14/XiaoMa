## 一、问题陈述

用户反馈：**不能自由选择任务进度；每个人基础不一样，应该支持自己选择任务以及完成度。**

经对 `docs/` 全部文档与 `backend/` 实现逐处核对，根因不是界面缺按钮，而是**任务生成算法把学习路径锁成了单轨**：

| # | 现象 | 代码位置 | 本质 |
| --- | --- | --- | --- |
| 1 | 想学第 3 章必须先做完前两章 | `services/daily_task_service.py:135-149` `_build_today_tasks()`：取「最早未完成计划日的**全部**知识点」整批下发 | 任务为系统指定，用户零选择权 |
| 2 | 课程目录只读，不能从知识点直接开学 | `frontend/app/(main)/learn/LearnClient.tsx`：仅展示章节知识点 + 「向 AI 提问」 | 学习入口只有「今日任务」一条 |
| 3 | 完成只有二值，没有「学了一半」 | `models/daily_task.py:36` `pending/learning/completed`；`models/learning_plan.py:36` `pending/completed` | 无法表达真实学习进度 |
| 4 | 「我会了」没有直达验证的路径 | `POST /mastery/self-report`、`/mastery/skip-check` 分散在「能力诊断」页；学习路径上无入口 | 基础好的用户被迫重复学 |
| 5 | 无章节级完成度 | `mastery_service.py` 仅按课程聚合 `mastered_percent` | 用户看不到「我学到哪了」 |
| 6 | 未完成任务次日被重新生成，学习中断感强 | `daily_task_service.py:93-126` 滚动追赶每日重取最早计划日 | 「学习中」不跨天延续 |

### 1.1 已具备、本次直接复用的能力（不重复造）

| 能力 | 现有实现 | 阶段 7 用法 |
| --- | --- | --- |
| 知识点 7 态掌握度 | `knowledge_mastery` + `mastery_evidence`（只追加） | 进度两个轴的唯一事实来源 |
| 发布校验 | `CoursePublicationService.resolve_task_refs()`（published + 课时归属校验） | 自选任务的准入闸，一行不改 |
| 单知识点跳级验证 | `POST /api/v1/diagnosis/placement`，`PlacementIn.knowledge_point_codes`（≤20）、`questions_per_point`（1—3，2 题全对才判掌握） | 「我会了，测一测」**零新增后端能力** |
| 任务防重复 | `daily_tasks` 唯一约束 `user_date_kp` + IntegrityError 兜底 | 自选与自动生成共用同一道闸 |
| 任务完成证据链 | `DailyTaskService.complete_task()` → `MasteryService.report_self_completed()` | 自选任务复用，仍然只写自述证据 |

## 二、设计原则（与既有铁律逐条对齐）

| 铁律 | 出处 | 本方案如何遵守 |
| --- | --- | --- |
| 用户点完成不得标记 `mastered` | PRD 6.1 | 自选任务完成 = 自述证据，路径上不存在 `自述 → mastered` 分支 |
| 课程体系由结构化数据维护，AI 不得创造 | PRD 3.2 | 自选只能从库内已发布课程的知识点中选，不新增课程/知识点写入入口 |
| 未掌握先修只提示补学、不自动跳过 | 阶段 5/6 口径 | 自选返回 `prerequisite_warnings`，**提醒但不阻塞** |
| 计划调整保留版本历史 | PRD 9 | 自选不产生计划版本，只标 `plan_item.completed` |
| 分层 API → Service → Repository；Agent 不得直连库 | CLAUDE.md 6/7 | 新增 `SelfStudyService` / `ProgressSummaryService`，Agent 工具清单**不新增**写入口 |
| 数据库变更必须 Alembic | CLAUDE.md 8 | 单一迁移，`down_revision = "9c1f4a7b2d3e"` |
| 不得实现未经确认的功能 | CLAUDE.md 13 | 本文档即确认载体，四项核心决策已由产品负责人选定 |

### 2.1 核心概念：两个轴必须分开

这是本阶段所有设计的地基，混淆就会造出「假进度」：

| 轴 | 含义 | 驱动来源 | 状态集合 | 能否用于跳过 |
| --- | --- | --- | --- | --- |
| **学习完成度**（进度轴） | 我有没有花时间学完这段内容 | 用户动作：开始、自述学完 | `not_started` / `in_progress` / `learned` | 否 |
| **掌握度**（证据轴） | 系统验证我是否真的会 | 测验 / 练习 / 诊断证据 | 7 态（`mastered` 最高） | 是，且只认 `mastered` |

> 前端两个百分比**分开显示、分别命名**：「学习完成 62%」与「已验证掌握 38%」。不合成单一进度条，否则用户会以为「学完了 = 会了」，与 PRD 6.1 直接冲突。

## 三、功能设计

### F1 自主选题（知识点级）

**用户视角**：在「课程学习」页浏览完整目录，任意点一个知识点 → 「加入今日学习」，它就出现在首页今日任务里，立刻可学。

**规则**：

1. 粒度 = 知识点（与 194 个知识点、7 态掌握度一一对应）。
2. 准入校验：
   - 知识点不存在 → `404`
   - 所属课程非 `published` 或知识点无连载中的课时 → `409`（复用 `resolve_task_refs()` 的既有异常）
   - 该知识点已 `mastered` → `409`，提示「已通过验证，建议去做复习或练习巩固」，不重复排学习任务
3. 幂等：同一用户 + 同一天 + 同一知识点已存在任务 → 返回既有任务，`created=false`。由既有唯一约束 `user_date_kp` 兜底。
4. 先修提示（不阻塞）：返回 `prerequisite_warnings[]`（未掌握的前置知识点 code + 名称），前端黄条提示「建议先学 X」，用户仍可继续。
5. 计划归属：
   - 该知识点**在当前生效计划版本内** → 任务挂 `plan_id`，完成时同步 `plan_item.completed`（即「自选即顶替」，滚动追赶自然前进）
   - 该知识点**不在当前计划内**（如计划只排了 `python-basics`，用户自选 `python-advanced`）→ `plan_id = NULL`，仅记任务与自述证据，不动计划
6. 撤回：仅 `source='self_selected'` 且 `status != 'completed'` 可删；已完成任务不可删（历史不可篡改）。

**与自动生成的关系（关键冲突，必须处理）**：

现状是「当天存在任何任务就不生成」。若不改，用户自选一个知识点后，今天的计划任务就再也不会生成。因此：

- 判断「是否需要生成」时**只看 `source='plan'`**；
- 生成时先取当天已存在任务的知识点集合（含自选），**从候选里剔除**，避免撞唯一约束；
- 输出层把两类任务**分组返回**，前端分区展示。

### F2 三档学习完成度

复用既有 `daily_tasks.status`，不新增状态机，只补齐语义与展示：

| status | 对外标签 | 触发 | 跨天行为 |
| --- | --- | --- | --- |
| `pending` | 未开始 | 任务生成 / 自选加入 | 若未开始且已过期 → 由滚动追赶重新下发（保留旧记录） |
| `learning` | 学习中 | `POST /daily-tasks/{id}/start` | **跨天保留在今日列表**，标 `carried_over=true` 与「已持续 N 天」；不再重复生成同知识点任务 |
| `completed` | 已学完（未验证） | `POST /daily-tasks/{id}/complete` | 写自述证据；提示「学完 ≠ 掌握，建议测一测」 |

**逾期任务收敛**：`carried_over` 最多取最近 7 天内未完成的任务，超出部分折叠为「更早有 N 个未完成任务」摘要，避免列表无限膨胀。本期默认 7 天，可在 `SelfStudyService` 常量里改。

### F3 课程 / 章节进度总览（两轴）

`GET /api/v1/progress/summary?course_code=` 一次返回课程级与章节级聚合，前端直接渲染：

- `kp_total` / `kp_started`（有学习记录）/ `kp_learned`（自述及以上）/ `kp_mastered`（有验证证据）
- `minutes_total` / `minutes_learned`（按 `estimated_minutes` 加权）
- `learning_percent` = 已学分钟 / 总分钟
- `mastery_percent` = 已验证掌握 / 总数

口径固定并写进注释：**`self_reported_completed` 计入 `kp_learned`，不计入 `kp_mastered`、不计入 `mastery_percent`。**

### F4 「我会了，测一测」（跳过路径）

零新增后端接口，复用 `POST /api/v1/diagnosis/placement`：

```
body: { "knowledge_point_codes": ["python-basics-02-01"], "questions_per_point": 2 }
→ QuizAttemptOut → 前端跳 /quiz?attempt=<id>（既有路由）
→ 2 题全对 → 写 placement 证据 → mastered → skip-check 自动放行
```

入口放在三处：课程目录知识点行、今日任务卡、「能力诊断」页薄弱项。题量不足（<2 题）时后端已抛 `409`，前端提示「该知识点题量不足，先用练习验证」。

**这条路径是「基础不一样」的正解**：不放开自述免修，因此 PRD 6.1 与阶段 5「自述不能跳过」的测试口径全部不动。

## 四、数据模型与迁移

单一迁移：`alembic/versions/xxxx_add_self_study_progress.py`，`down_revision = "9c1f4a7b2d3e"`。

### 4.1 `daily_tasks` 变更

| 列 | 变更 | 说明 |
| --- | --- | --- |
| `plan_id` | `NOT NULL` → `NULL` | 计划外自选任务（跨课程自学）不挂计划；应用层保证 `source='plan'` 时必填 |
| `source` | 新增 `VARCHAR(16) NOT NULL DEFAULT 'plan'` + `CHECK IN ('plan','self_selected')` | 区分任务来源 |
| 索引 | 新增 `(user_id, task_date, source)` | 支撑「只查计划任务」与分组输出 |

SQLite 加 CHECK 必须重建表，沿用阶段 6 已验证的 `batch_alter_table`（`recreate="always"`）一次完成；重建时显式声明既有约束（`user_date_kp` 唯一约束、`status` CHECK），避免 batch 反射丢约束。`downgrade()` 用 batch 逆序还原：删索引 → 删 `source` → `plan_id` 恢复 `NOT NULL`（先 `DELETE` 无法回填的计划外自选任务，或直接改回非空并断言无 NULL 行）。

### 4.2 不改的表

`knowledge_mastery`、`mastery_evidence`、`exercise_attempts`、`learning_plan_versions`、`learning_plan_items` **零结构变更**。进度完全由既有数据聚合，不做冗余冗余存列。

## 七、验收标准

### 7.1 功能验收（手动）

1. 「课程学习」页展开 `python-basics` → 每个知识点显示两轴状态与时长；章节标题右侧显示「学习完成 40% / 已验证 20%」。
2. 点第 5 章任一知识点「加入今日学习」→ 首页今日任务出现该任务，标「自选」；同一天重复点击不再新增（`created=false`）。
3. 自选后仍未生成计划任务的情况下，首页仍会自动生成当天计划任务，二者并存不互相吞掉。
4. 点「开始学习」→ 状态「学习中」；次日打开首页，该任务仍在列表并标「已持续 1 天」，且同知识点不再生成新任务。
5. 点「已学完」→ 状态「已学完（未验证）」，学习完成度上升、掌握度**不变**；提示引导「测一测」。
6. 点「我会了，测一测」→ 生成 2 题诊断测验 → 全对后该知识点显示「已掌握」，`skip-check` 放行，计划不再安排它。
7. 自选计划内知识点并完成后 → 学习计划页对应项目变 `completed`，滚动追赶前进一格。
8. 计划外课程（如 `python-advanced`）自选完成 → 计划纹丝不动，仅任务与证据留痕。
9. 撤回未完成自选任务 → 从今日列表消失、无残留证据；撤回已完成任务 → `409`。
10. 已掌握知识点再次自选 → `409` 并给出复习引导。
11. 草稿课程 `software-engineering-deploy` 的知识点无法自选（`409`）。

## 八、边界：明确不做

- ❌ 不新增课程 / 知识点 / 课时写入入口，不允许 AI 生成学习内容（PRD 3.2 不变）

### 12.3 与方案的偏差（3 处，均已在本节说明理由）

1. **`tasks` 字段范围**：方案写「全部任务平铺」，实施改为「当天任务」；跨天承接单独放 `carried_over_tasks`。理由：避免旧前端把昨天任务重复渲染一遍，兼容优先。
2. **计划外自选的测试手法**：测试库只播种 `python-basics` 的知识点（其余课程是纯目录，无知识点），因此用「从生效计划版本移除该知识点」构造计划外场景，而不是跨课程自选。业务代码路径完全一致（`_plan_context` 找不到 item → `plan_id=None`）。
3. **新增 `daily_task_presenter.py`**：方案未提，属实现细节——任务输出装配被两处复用，抽成纯函数避免文案与字段漂移。

### 12.4 实施中发现并修掉的真实缺陷

| # | 缺陷 | 后果 | 修法 |
| --- | --- | --- | --- |
| 1 | 「学习中」任务跨天承接后，`plan_item` 仍是 `pending`，滚动追赶会重新下发同一知识点 | 用户学了三天还在原地 | `_build_today_tasks` 把承接窗口内的 kp 一并从候选剔除（测试 #9） |

### 12.6 手动验收

```bash
cd backend
.venv/Scripts/python -m alembic upgrade head
.venv/Scripts/python -m app.cli seed-catalog
uvicorn app.main:app --reload --port 8000
cd ../frontend && npm run dev
```

1. 打开「课程学习」：顶部显示「学习完成 X%（分钟）」「已验证掌握 Y%（知识点个数）」两个数字；章节标题右侧显示两项百分比。
2. 任选一个知识点点「加入今日学习」→ 首页出现「我自己选的」分区；同一天重复点不会新增（提示已在今日任务中）。
3. 若当天计划任务尚未生成，首页仍会生成「按计划安排」任务，两类并存 —— 自选不会吞掉计划。
4. 点「开始学习」→ 状态变「学习中」；次日打开首页，该任务出现在「继续学习」并显示「已持续 N 天」，同一知识点不会重复下发。
5. 点「标记学完」→ 显示「已学完（未验证）」，课程页「学习完成%」上升而「已验证掌握%」不变。
6. 点「我会了，测一测」→ 直接进入 2 题诊断测验；两题全对后该知识点变「真正掌握」，「已验证掌握%」上升，计划不再安排它。
7. 在「学习计划」页确认计划后自选一个计划内知识点并完成 → 对应计划项目变已完成，滚动追赶前移一格。
8. 撤回未完成的自选任务 → 从首页消失；已完成的任务没有「撤回」按钮（接口也会 409）。
